# عقد API لنظام الإدارة والموارد البشرية

**الملف المعتمد:** `openapi.yaml`، بصيغة OpenAPI 3.0.3، وفيه 307 عمليات.

**الحالة:** الإصدار 1.0، وقرارات مالك المشروع مطبقة فيه، ولا توجد أسئلة مفتوحة داخله. لم يُجرَّب بعد مع مولدات الكود أو خادم فعلي.

## الملفات

| الملف | الغرض |
|---|---|
| `openapi.yaml` | العقد الذي تعطيه للذكاء الاصطناعي |
| `CONVENTIONS.md` | قواعد العقد وصيغ البيانات |
| `QUESTIONS.md` | قرارات مالك المشروع المعتمدة، وهي مطبقة في العقد |
| `audit/` | تقارير التدقيق الثلاثة كما كتبها المدققون قبل الإصلاح |
| `modules/` | مسودات الوحدات، وهي مصدر الدمج فقط، فلا تعطها للذكاء الاصطناعي |
| `tools/` | سكربتات الدمج والإصلاح والقرارات التي تنتج `openapi.yaml` |

## طريقة الاستخدام مع الذكاء الاصطناعي

أعطه `openapi.yaml` و`CONVENTIONS.md`، وأعطه `متطلبات_وتصميم_النظام.md` إذا كان العمل يحتاج قواعد العمل. ثم استخدم الطلب المناسب:

**للباك إند**

```text
ابنِ وحدة <اسم الوحدة> بـASP.NET Core وABP، مطابقة لـopenapi.yaml في المسارات والحقول وأكواد الأخطاء. طبق كل ما في x-server-requirements وx-global-rules. x-permission هو فحص الخادم. لا تضف مسارًا أو حقلًا غير موجود في العقد، وإذا احتجت ذلك فأخبرني أولًا.
```

**لواجهات Flutter**

```text
ابنِ شاشات <اسم الوحدة> بـFlutter، باستخدام عميل مولد من openapi.yaml. استخدم operationId الكامل اسمًا للدالة، وx-allowed-roles لإظهار الشاشات، وerror.code لمعالجة الأخطاء بدل نص الرسالة. لا تخمن حقلًا غير موجود في العقد.
```

**لتصميم UI/UX**

```text
صمم شاشات <اسم الوحدة> لكل دور في x-allowed-roles، بالعربية والإنجليزية، مع حالات التحميل والفراغ والخطأ من x-error-codes. اعرض فقط الحقول الموجودة في DTO الخاص بذلك الدور.
```

ابدأ بالعمليات التي تحمل `x-release: 1`، وابنِ وحدة واحدة في كل مرة.

## ما الذي يحقق عدم أخطاء الربط

- توليد عميل Flutter من الملف، بدل كتابة الاستدعاءات يدويًا.
- اختبار يقارن مسارات الخادم الفعلية بالعقد.
- اختبار واحد لكل صيغة بيانات: التعدادات، والتاريخ، والوقت، و`null`.
- أي تغيير في الربط يبدأ من `openapi.yaml`، ثم الباك، ثم الفرونت.

## ما لم يُفحص

- **مولدات الكود:** لم تُشغَّل على العقد، وأولها Dart وC#.
- **السلوك الفعلي:** القواعد المكتوبة في الأوصاف وعود في العقد، ولم يُبنَ خادم يطبقها بعد.
- **مراجعة بعد الإصلاح:** الفحص الآلي أُعيد بعد الإصلاحات، لكن المدققين لم يعيدوا مراجعة العقد.
- **تقارير `audit/`:** تصف العقد قبل الإصلاح، فبعض ملاحظاتها أُصلح.

## ملاحظات لم تُعالج بعد

**تحسينات صغيرة أو متوسطة مؤجلة:**
- توحيد الأسماء: INT-25، وINT-36، وINT-37، وINT-38، وINT-39، وINT-45.
- فهرس أكواد الأخطاء وبيانات الخطأ: INT-21، وINT-42.
- الخصوصية الثانوية: SEC-17، وSEC-18، وSEC-19، وSEC-20، وSEC-21، وSEC-22، وSEC-23، وSEC-25، وSEC-29، وSEC-32، وSEC-33.
- أخرى: COV-16، وCOV-19، وCOV-28، وCOV-30، وINT-35، وINT-40، وINT-41، وINT-46، وINT-47.

## تحذيرات الفحص الآلي المقبولة

- `no-invalid-media-type-examples` مع `null`: صيغة `allOf` مع `nullable` مقصودة، وتحتاج تأكيدًا عند تجربة المولدات.
- `no-ambiguous-paths`: يحلها قيد `:guid` على مسارات الخادم.
- `exclusiveMinimum`: قصور في أداة الفحص، فالصيغة صحيحة في OpenAPI 3.0.
