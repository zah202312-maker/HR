# Privacy and Security Audit of the API Contract

Audited: `api-contract/openapi.yaml` (OpenAPI 3.0.3, 308 operations, 496 schemas), against `متطلبات_وتصميم_النظام.md` and `CONVENTIONS.md`. No contract, module, or requirements file was changed.

## Summary

| Severity | Count |
|---|---|
| CRITICAL (leak or broken protected rule) | 2 |
| MAJOR (likely exposure or missing check) | 11 |
| MINOR (hardening) | 20 |
| **Total** | **33** |

The DTO layer holds up: no forbidden field was found in any role's response tree. The serious problems are in **who can obtain a role, a permission, or another person's login**. Those paths reach complaint and financial data without touching any DTO the field walk would flag.

Contract-level findings describe what the contract allows or fails to forbid. No backend exists yet, so none was exploited.

## Findings

Sorted by severity. "Fix" is a change for the contract owner to apply, since this audit edits nothing. Items marked **owner decision** change or clarify a stated requirement.

## What could not be verified

- **Runtime behavior.** Prose such as "the server checks" is a promise. No backend was tested.
- **Export file contents.** PDF and Excel responses have no schema, so only the descriptions were checked.
